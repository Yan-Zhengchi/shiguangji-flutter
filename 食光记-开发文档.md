### 1.3 统一响应与全局异常

```java
@Data
public class Result<T> {
    private int code;          // 0 成功，非 0 见错误码表
    private String message;
    private T data;
    public static <T> Result<T> ok(T data) { /* code=0 */ }
    public static <T> Result<T> fail(ErrorCode ec) { /* ... */ }
}

@RestControllerAdvice
public class GlobalExceptionHandler {
    @ExceptionHandler(BizException.class)        // 业务异常 → 4xx + 错误码
    @ExceptionHandler(MethodArgumentNotValidException.class) // 参数校验 → 40010
    @ExceptionHandler(Exception.class)            // 兜底 → 50000，日志告警
}
```

**错误码表（节选）**

| code | 含义 |
|---|---|
| 0 | 成功 |
| 20001 | 用户名或密码错误 |
| 20002 | 用户名已存在 |
| 30001 | 菜谱不存在 |
| 30002 | 无权操作他人菜谱 |
| 40001 | 家庭不存在 / 非成员 |
| 40100 | 未登录 / Token 失效 |
| 40010 | 参数校验失败 |
| 50000 | 系统内部错误 |

## 4. 关键后端代码骨架

### 4.1 JWT 过滤器（节选）

```java
@Component
@RequiredArgsConstructor
public class JwtAuthenticationFilter extends OncePerRequestFilter {
    private final JwtUtil jwtUtil;
    private final StringRedisTemplate redis;

    @Override
    protected void doFilterInternal(HttpServletRequest req, HttpServletResponse resp,
                                    FilterChain chain) throws ServletException, IOException {
        String token = resolveBearer(req.getHeader("Authorization"));
        if (token != null) {
            Claims c = jwtUtil.parse(token);                       // 失败抛 40100
            if (Boolean.TRUE.equals(redis.hasKey("token:blacklist:" + c.getId())))
                throw new BizException(ErrorCode.UNAUTHORIZED);
            SecurityContextHolder.getContext()
                .setAuthentication(new UsernamePasswordAuthenticationToken(
                    c.getSubject(), null, List.of()));
        }
        chain.doFilter(req, resp);
    }
}
```

### 4.2 首页瀑布流（读缓存 → 回源）

```java
public List<RecipeCardVO> home(Long categoryId, int page, int size) {
    String key = "recipe:home:" + categoryId + ":" + page;
    List<RecipeCardVO> cached = redisForList(key);
    if (cached != null) return cached;

    List<RecipeCardVO> list = recipeMapper.selectHomeCards(categoryId, page, size);
    // 乱序双列由前端瀑布流组件自行分流；后端仅按 (favorite_count*2 + view_count) 倒序

    return list;
}
```

### 5.3 通用玻璃组件（还原设计稿玻璃公式）

```dart
// core/widgets/glass_card.dart
class GlassCard extends StatelessWidget {
  const GlassCard({super.key, required this.child,
    this.radius = 20, this.padding = const EdgeInsets.all(16), this.tint = 0.12});
  final Widget child; final double radius; final EdgeInsets padding; final double tint;

  @override
  Widget build(BuildContext context) => ClipRRect(
    borderRadius: BorderRadius.circular(radius),
    child: BackdropFilter(                       // 对应 BACKGROUND_BLUR 16
      filter: ImageFilter.blur(sigmaX: 16, sigmaY: 16),
      child: Container(
        padding: padding,
        decoration: BoxDecoration(
          color: Colors.white.withValues(alpha: tint),      // 白 12% 填充
          borderRadius: BorderRadius.circular(radius),
          border: Border.all(color: Colors.white.withValues(alpha: 0.16)), // 白 16% 描边
          boxShadow: const [
            BoxShadow(color: Color(0x1F2E6B8C), blurRadius: 20, offset: Offset(0, 6)),
          ],
        ),
        child: child,
      ),
    ),
  );
}
```

> 性能提示：`BackdropFilter` 开销较大——首页瀑布流中**只有滚动方向上少量卡片**使用真实 BackdropFilter，长列表项可用纯色 `white10 + 边框` 降级（视觉差异极小，帧率稳定 60）。光斑（暖橙/亮蓝 radial）用 `RadialGradient` 的 `DecoratedBox` 放在 Stack 底层，无需 blur。

## 7. Docker 封装与 NAS 一键部署

> 目标：**后端（Spring Boot）+ 数据库（MySQL 8）+ 缓存（Redis 7）全部容器化**，在 NAS 上 `docker compose up -d` 一键运行整套后端。容器随删随建，数据与配置全部落在 NAS 目录，不丢。

### 7.1 交付物目录（`deploy/` 随仓库提交）

### 7.2 后端 Dockerfile（多阶段构建）

```dockerfile
# ---- 构建层：Maven 编译 ----
FROM maven:3.9-eclipse-temurin-17 AS build
WORKDIR /workspace
COPY pom.xml .
RUN mvn -q dependency:go-offline              # 先缓存依赖层，改代码不重下依赖
COPY src ./src
RUN mvn -q clean package -DskipTests

# ---- 运行层：精简 JRE ----
FROM eclipse-temurin:17-jre-jammy
LABEL app="shiguangji-server"

# 时区（MySQL/日志时间对齐东八区）
ENV TZ=Asia/Shanghai
RUN ln -sf /usr/share/zoneinfo/$TZ /etc/localtime && echo $TZ > /etc/timezone

# 非 root 运行
RUN groupadd -r app && useradd -r -g app app
WORKDIR /app
COPY --from=build /workspace/target/shiguangji-server.jar app.jar
USER app

EXPOSE 8080
ENV JAVA_OPTS="-Xms256m -Xmx512m"
ENTRYPOINT ["sh", "-c", "java $JAVA_OPTS -jar app.jar"]

# 健康检查（需要 spring-boot-starter-actuator 暴露 /actuator/health）
HEALTHCHECK --interval=30s --timeout=5s --retries=3 \
  CMD curl -fsS http://localhost:8080/actuator/health || exit 1
```

> 需在 pom.xml 追加：`org.springframework.boot:spring-boot-starter-actuator`，并在 application.yml 中 `management.endpoints.web.exposure.include: health`。
> 最终镜像 ≈ 300MB（JRE + jar），比直接把 Maven 镜像搬上 NAS 小约 1GB。

### 7.3 docker-compose.yml（核心编排文件）

```yaml
name: shiguangji

services:
  app:
    build:
      context: ..                    # Dockerfile 在 deploy/，构建上下文为仓库根
      dockerfile: deploy/Dockerfile
    image: shiguangji-server:latest  # 或你的镜像仓库地址：registry.xxx/shiguangji-server:1.0.0
    container_name: shiguangji-app
    restart: unless-stopped
    ports:
      - "8080:8080"                  # NAS 内网访问 http://nas-ip:8080
    environment:
      MYSQL_HOST: mysql              # 容器网络内服务名直达，不映射宿主机端口
      MYSQL_USER: ${MYSQL_USER}
      MYSQL_PASSWORD: ${MYSQL_PASSWORD}
      REDIS_HOST: redis
      REDIS_PASSWORD: ${REDIS_PASSWORD}
      JWT_SECRET: ${JWT_SECRET}
      OSS_ENDPOINT: ${OSS_ENDPOINT:-}
      OSS_BUCKET: ${OSS_BUCKET:-}
    depends_on:
      mysql:
        condition: service_healthy   # 等 MySQL 就绪再启动 app
      redis:
        condition: service_healthy
    networks: [sgj-net]

  mysql:
    image: mysql:8.0
    container_name: shiguangji-mysql
    restart: unless-stopped
    # 不映射宿主机 3306：只允许 app 容器访问，NAS 网络内不暴露
    environment:
      MYSQL_ROOT_PASSWORD: ${MYSQL_PASSWORD}
      MYSQL_DATABASE: shiguangji
      TZ: Asia/Shanghai
    volumes:
      - ${DATA_DIR}/mysql/data:/var/lib/mysql           # 数据持久化到 NAS
      - ./mysql/init.sql:/docker-entrypoint-initdb.d/init.sql:ro   # 首启自动建表
    command: >
      --character-set-server=utf8mb4
      --collation-server=utf8mb4_general_ci
      --default-time-zone=+08:00
    healthcheck:
      test: ["CMD", "mysqladmin", "ping", "-h", "localhost", "-p$$MYSQL_ROOT_PASSWORD"]
      interval: 10s
      timeout: 5s
      retries: 10
      start_period: 30s
    networks: [sgj-net]

  redis:
    image: redis:7-alpine
    container_name: shiguangji-redis
    restart: unless-stopped
    # 不映射宿主机 6379
    command: >
      redis-server
      --requirepass ${REDIS_PASSWORD}
      --appendonly yes
      --maxmemory 256mb
      --maxmemory-policy allkeys-lru
    volumes:
      - ${DATA_DIR}/redis/data:/data
    healthcheck:
      test: ["CMD", "redis-cli", "-a", "${REDIS_PASSWORD}", "ping"]
      interval: 10s
      timeout: 3s
      retries: 10
    networks: [sgj-net]

  # ---------- 可选：HTTPS 反代（不需要可整段删除）----------
  # nginx:
  #   image: nginx:alpine
  #   container_name: shiguangji-nginx
  #   restart: unless-stopped
  #   ports: ["443:443", "80:80"]
  #   volumes:
  #     - ./nginx.conf:/etc/nginx/conf.d/default.conf:ro
  #     - ${DATA_DIR}/certs:/etc/nginx/certs:ro
  #   depends_on: [app]
  #   networks: [sgj-net]

networks:
  sgj-net:
    driver: bridge
```

### 7.5 NAS 部署流程（从零到跑通）

```bash
# ---------- 一次性：开发机构建并推送镜像 ----------
docker build -t <你的镜像仓库>/shiguangji-server:1.0.0 -f deploy/Dockerfile .
docker push <你的镜像仓库>/shiguangji-server:1.0.0
# 国内推荐：阿里云容器镜像服务 ACR（免费个人版）或 NAS 自带 Registry；
# 若 NAS 不方便外网，也可 docker save | ssh 后 docker load 离线导入

# ---------- NAS 上首次部署 ----------
mkdir -p /volume1/docker/shiguangji
cd /volume1/docker/shiguangji
# 上传 deploy/ 目录（git clone 或 SMB 拷贝）
cp .env.example .env && vi .env       # 填好 DATA_DIR / 密码 / JWT_SECRET
docker compose up -d                  # ★ 一键启动：拉取镜像 + 建表 + 启动三容器
docker compose ps                     # 应看到 app / mysql / redis 均 healthy
curl http://localhost:8080/actuator/health   # {"status":"UP"}

# ---------- 日常运维 ----------
docker compose logs -f app            # 看日志
docker compose up -d --build app      # 改了代码重新构建并更新（仅本地构建场景）
docker compose pull app && docker compose up -d app   # 镜像仓库模式更新
docker compose down                   # 停止整套（数据卷不受影响）
```

### 7.6 NAS 注意事项（踩坑清单）

| 坑 | 对策 |
|---|---|
| NAS 上 Docker Hub 拉不动 | 在 compose 文件同级加 `registry-mirrors`（Docker 设置里），或用阿里云 ACR 镜像地址 |
| MySQL/Redis 端口暴露到局域网 | 本方案**不映射宿主机端口**，只有 app 的 8080 对外开放；如必须宿主机访问，改 `127.0.0.1:3306:3306` |
| 时区错乱（created_at 差 8 小时） | 三处已对齐：容器 `TZ=Asia/Shanghai`、MySQL `--default-time-zone=+08:00`、JDBC `serverTimezone=Asia/Shanghai` |
| NAS 内存小（2-4GB） | compose 已给 app 限定 `-Xmx512m`、redis `maxmemory 256mb`；MySQL 8 可在 command 追加 `--performance-schema=OFF` 再省约 100MB |
| 数据丢失 | 数据全在 `${DATA_DIR}` 下；`backup.sh` 每日 dump + NAS 快照双保险 |
| 外网访问 | 建议 NAS 内网直连 App；如需公网，走 NAS 厂商 DDNS/内网穿透 + nginx 反代 + 免费证书（Let's Encrypt），**不要直接暴露 8080** |

### 7.7 backup.sh（每日备份脚本）

```bash
#!/bin/sh
# 放入 deploy/，由 NAS 定时任务（群晖：控制面板→任务计划）每日执行
BACKUP_DIR="${DATA_DIR:-/volume1/docker/shiguangji}/backup"
mkdir -p "$BACKUP_DIR"
docker exec shiguangji-mysql mysqldump -u root -p"$MYSQL_PASSWORD" shiguangji \
  | gzip > "$BACKUP_DIR/shiguangji-$(date +%Y%m%d).sql.gz"
find "$BACKUP_DIR" -name "*.sql.gz" -mtime +14 -delete    # 只保留 14 天
```
